# Releasing a Kyro version

Installed wallets update themselves from the GitHub releases of
`shuntraa/kyro-wallet` (see SECURITY.md "Automatic updates"). They only install
a package **signed by Kyro's update key** and newer than the running version.

## 1. The signing key (one time only)

Generated with the Tauri CLI, without a password:

```sh
cd apps/desktop
pnpm tauri signer generate --ci -w "C:\Users\<you>\.tauri\kyro-updater.key"
```

- `kyro-updater.key`: **private** key. Never in the repository, never displayed, kept offline
  (backup copy). Losing it = installed wallets can no longer receive updates
  (a version carrying a new public key would have to be reinstalled by hand).
- `kyro-updater.key.pub`: **public** key, copied as-is (the base64 text of the file)
  into `apps/desktop/src-tauri/tauri.conf.json` → `plugins.updater.pubkey`. It is compiled
  into the binary: changing the key requires a version signed by the **old** key that embeds
  the new one.

Current key: generated on 2026-11-01, private key in `C:\Users\<you>\.tauri\kyro-updater.key`.

## 2. GitHub secrets

Repository → *Settings* → *Secrets and variables* → *Actions* → *New repository secret*:

| Secret | Value |
|---|---|
| `TAURI_SIGNING_PRIVATE_KEY` | the **contents** of the `kyro-updater.key` file (a single base64 line) |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | the current key has **no** password: do not create this secret (GitHub refuses an empty value; a missing secret equals `''` in the job). Create it only if the key is ever regenerated with a password |

`GITHUB_TOKEN` is provided by Actions (the job needs `permissions: contents: write`).

## 3. What the build produces

`tauri.conf.json` → `bundle.createUpdaterArtifacts: true`: each build signs, alongside the
installers, the update package for its platform:

| Platform | Package | `latest.json` key read by Kyro |
|---|---|---|
| Windows | `Kyro_X.Y.Z_x64-setup.exe` + `.sig` (NSIS, installed in passive / silent mode) | `windows-x86_64-nsis`, otherwise `windows-x86_64` |
| macOS | `Kyro_<arch>.app.tar.gz` + `.sig` | `darwin-aarch64-app` / `darwin-x86_64-app`, otherwise `darwin-<arch>` |
| Linux | `Kyro_X.Y.Z_amd64.AppImage` + `.sig` | `linux-x86_64-appimage`, otherwise `linux-x86_64` |

Kyro refuses a package of a type other than its installation (`.msi`, `.deb`, `.dmg`…), a URL
outside `https://github.com/shuntraa/kyro-wallet/releases/download/`, and a version that is
not strictly newer.

Local build **without** the key (development): the CLI refuses to sign; disable the update
artifacts for this build:

```sh
pnpm tauri build --config '{"bundle":{"createUpdaterArtifacts":false}}'
```

## 4. Publishing

1. Bump the version everywhere (same number): `apps/desktop/src-tauri/tauri.conf.json`
   (`version`), `Cargo.toml` (`workspace.package.version` and the `wallet-core = "=X.Y.Z"`
   requirement in `apps/desktop/src-tauri/Cargo.toml`), `apps/desktop/package.json`; refresh
   `Cargo.lock` (`cargo check`).
2. Push the tag `vX.Y.Z` → `.github/workflows/release.yml` builds the 3 platforms, signs the
   update packages and creates a **draft** release.
3. Check the draft (files, `latest.json`, `SHA256SUMS`), then **publish** it: that makes it
   "latest", so the website links and the installed wallets pick it up (a pre-release, tag
   with a `-`, is never taken).
4. Submit the Windows installers to Microsoft for SmartScreen (section 7).

## 5. The release workflow (`.github/workflows/release.yml`)

- **build** (Windows `windows-2022`, macOS `macos-14` universal binary, Linux `ubuntu-22.04`):
  fails if the tag is not `v` + `tauri.conf.json` `version`; Rust from `rust-toolchain.toml`;
  `tauri-action` (build only, no upload) with `TAURI_SIGNING_PRIVATE_KEY` /
  `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, so each update package gets its `.sig`; files renamed
  to fixed names.
- **release**: checks each `.sig` (prehashed, key ID of `plugins.updater.pubkey`, version),
  writes `latest.json` and `SHA256SUMS`, creates the draft release (`softprops/action-gh-release`).

Release assets (fixed names, linked by the website through `releases/latest/download/<name>`):

| File | Role |
|---|---|
| `Kyro-windows-x64-setup.exe` + `.sig` | NSIS installer, also the Windows update package |
| `Kyro-windows-x64.msi` | MSI installer (does not update itself) |
| `Kyro-macos.dmg` | macOS installer (universal) |
| `Kyro-macos.app.tar.gz` + `.sig` | macOS update package (universal) |
| `Kyro-linux-x86_64.AppImage` + `.sig` | AppImage, also the Linux update package |
| `Kyro-linux-amd64.deb` | Debian/Ubuntu package (updated by the package manager) |
| `latest.json`, `SHA256SUMS` | update manifest, checksums |

`latest.json` (generated by the workflow, not by `tauri-action`):

```json
{
  "version": "X.Y.Z",
  "notes": "...",
  "pub_date": "2026-11-01T12:00:00Z",
  "platforms": {
    "windows-x86_64-nsis": { "signature": "<content of the .sig>", "url": "https://github.com/shuntraa/kyro-wallet/releases/download/vX.Y.Z/Kyro-windows-x64-setup.exe" },
    "darwin-aarch64-app":  { "signature": "...", "url": ".../vX.Y.Z/Kyro-macos.app.tar.gz" },
    "darwin-x86_64-app":   { "signature": "...", "url": ".../vX.Y.Z/Kyro-macos.app.tar.gz" },
    "linux-x86_64-appimage": { "signature": "...", "url": ".../vX.Y.Z/Kyro-linux-x86_64.AppImage" }
  }
}
```

plus the generic keys `windows-x86_64`, `darwin-aarch64`, `darwin-x86_64`, `linux-x86_64`
(same entries). URLs are per version (`releases/download/<tag>/`), so an older manifest keeps
pointing to its own files. Third-party actions are pinned to commit SHAs (version in a comment).

## 6. Verifying after publication

```sh
curl -sL https://github.com/shuntraa/kyro-wallet/releases/latest/download/latest.json
```

must show the new version and one entry per platform. An installed wallet applies it on its
next close (check ≈ 45 s after launch), and shows "Kyro updated to X.Y.Z." at the
following startup.

## 7. Windows SmartScreen (unsigned installers)

The Windows installers are not code-signed. A browser download of an unsigned file carries the
"downloaded from the internet" mark (Mark of the Web), so SmartScreen shows "Windows protected
your PC" until the file has built reputation. That reputation is tied to the file's hash: every
release starts from zero. Never affected: updates applied by the in-app updater, and installs
through `install.ps1`, which fetch the file without that mark.

After publishing a release, submit both Windows installers to Microsoft, one submission per file:

1. Download `Kyro-windows-x64-setup.exe` and `Kyro-windows-x64.msi` from the **published**
   release (the exact files users get, so the hashes match).
2. Open <https://www.microsoft.com/en-us/wdsi/filesubmission>, sign in with a Microsoft account,
   choose **Software developer**, then fill in:

   | Field | Value |
   |---|---|
   | Product | Microsoft Defender Smartscreen |
   | Company name / Affected organization | Kyro Wallet |
   | Number of affected devices | 1 - 100 |
   | Submission priority | Low |
   | What do you believe this file is? | Incorrectly detected as malware/malicious |
   | Detection name | SmartScreen: Windows protected your PC (unrecognized app) |
   | Additional information | `Kyro Wallet vX.Y.Z, open-source (GPL-3.0-or-later) crypto wallet. Source and release: https://github.com/shuntraa/kyro-wallet/releases/tag/vX.Y.Z. SHA-256: <hash from SHA256SUMS>. Built by GitHub Actions from the public repository.` |

3. Complete the CAPTCHA and submit. Microsoft answers by email with the submission ID; keep it.

Microsoft does not guarantee that a submission clears SmartScreen for home users: reputation
mostly builds with downloads. The download page explains the warning (*More info* → *Run
anyway*) and points to the one-line command, which avoids it.

## 8. Microsoft Store

The Store package is `Kyro-windows-x64.msix` (identity `KyroWallet.KyroWallet`, publisher
`CN=7F2DA35F-5094-4C2D-9CB5-BC0ACBA1123A`, display name "Kyro Wallet", version `x.y.z.0`).
The release workflow builds it from the same `kyro-desktop.exe` and attaches it to the draft
release; it is **unsigned** (Partner Center signs it) and not part of `latest.json`. To build it
by hand (Windows SDK needed for `makeappx.exe` / `makepri.exe`):

```powershell
pnpm tauri build --no-bundle          # or any release build of kyro-desktop.exe
apps/desktop/packaging/msix/build-msix.ps1 -Exe target/release/kyro-desktop.exe -Out Kyro-windows-x64.msix
```

Packaging files live in `apps/desktop/packaging/msix/`: `AppxManifest.xml` (full-trust app,
`internetClient` + `runFullTrust`, Windows 10 1809+; USB access for Ledger / Trezor needs no
extra capability in a full-trust app), `Assets/` (logos, regenerated from the app icon by
`make-assets.ps1`). The package relies on the system WebView2 Evergreen runtime.

Behaviour when installed from the Store: Kyro detects its package identity
(`GetCurrentPackageFullName`) and never checks, downloads or installs its own updates; Settings
shows "Updates are handled by the Microsoft Store" instead of the toggle. App data stays in
`%APPDATA%\org.kyro.wallet`, which Windows redirects to the package's private folder
(`%LOCALAPPDATA%\Packages\KyroWallet.KyroWallet_<id>\LocalCache\Roaming\…`); it is removed when the
app is uninstalled, so users must keep their recovery phrase.

Local test install (optional): sign a **copy** with a throwaway self-signed certificate whose
subject is exactly the manifest publisher, trust it (`Cert:\LocalMachine\TrustedPeople`), then
`Add-AppxPackage`; remove the package and the certificate afterwards. Never commit that certificate.

Submitting in [Partner Center](https://partner.microsoft.com/dashboard) (Apps and games → Kyro Wallet):

1. **Start a submission** (first time: "Start your submission").
2. **Pricing and availability**: Free, markets, visibility (public).
3. **Properties**: category Finance (subcategory Personal finance), privacy policy URL
   `https://kyrowallet.com/privacy/`, website, support contact (GitHub issues), system
   requirements.
4. **Age ratings**: fill in the IARC questionnaire honestly (no user-generated content, no ads, no
   in-app purchases; users send and swap cryptocurrency).
5. **Packages**: upload `Kyro-windows-x64.msix` (Windows 10/11 desktop, x64). Partner Center
   checks the identity against the reserved name.
6. **Store listings** (English and French): description, short description, what's new,
   keywords, screenshots (PNG, 1920×1080), copyright.
7. **Submission options** → `runFullTrust` is a restricted capability: explain "Desktop
   (Win32) app packaged as MSIX; needs full trust for its Rust core, embedded Tor client and USB
   access to Ledger and Trezor hardware wallets."
8. **Submit to the Store**, then wait for certification (usually a few business days).

For each new version: tag the release, download `Kyro-windows-x64.msix` from the draft release,
create a new submission (Update), replace the package, update "What's new", submit.
